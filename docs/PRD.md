# Klip 产品需求文档 (PRD)

## 1. 产品概述

### 1.1 产品定位

Klip 是一个当前以 Windows 为 MVP 交付目标的桌面剪贴板管理器，解决操作系统剪贴板只能保存一条内容的限制，帮助用户高效管理复制粘贴历史。

### 1.2 目标用户

| 用户类型 | 使用场景 |
|----------|----------|
| 知识工作者 | 收集资料、整理笔记 |
| 开发者 | 复制代码片段、命令行 |
| 内容创作者 | 写作素材收集 |
| 数据录入人员 | 重复性粘贴操作 |

### 1.3 核心价值

- **效率提升** - 快速访问历史剪贴板内容，减少重复复制
- **隐私保护** - 本地存储，数据不上传云端
- **平台聚焦** - 当前 MVP 以后端 Windows 体验为主，后续扩展 macOS/Linux
- **轻量高效** - 低内存占用，快速启动

### 1.4 产品名称

**Klip** - 简短有力，K 开头有辨识度，易于记忆和搜索。

## 2. 功能需求

### Phase 1: MVP (最小可行产品)

#### F1: 剪贴板历史记录

| 属性 | 内容 |
|------|------|
| 描述 | 自动监听并保存剪贴板内容变化 |
| 用户场景 | 用户复制文本后，内容自动保存到历史列表 |
| 验收标准 | 1. 复制内容后 100ms 内出现在列表<br>2. 最多保存 100 条记录<br>3. 自动去重相同内容 |
| 技术要点 | 使用 arboard crate 轮询监听，SQLite 存储 |

#### F2: 多格式支持

| 属性 | 内容 |
|------|------|
| 描述 | 支持识别和存储不同类型的内容 |
| 用户场景 | 用户复制文本、图片、文件，都能正确保存和预览 |
| 验收标准 | 1. 正确识别文本、图片、文件路径<br>2. 图片显示缩略图预览<br>3. 文件显示文件名和数量 |
| 技术要点 | 检测剪贴板格式类型，图片 Base64 存储 |

#### F3: 全局快捷键唤起

| 属性 | 内容 |
|------|------|
| 描述 | 通过快捷键快速显示/隐藏主窗口 |
| 用户场景 | 用户在任何应用中按快捷键，Klip 窗口立即出现 |
| 验收标准 | 1. 当前默认快捷键为 `Ctrl+Alt+K`<br>2. 当前运行时支持 `Ctrl+Alt+<A-Z>` 范围内的窗口快捷键配置<br>3. 修改后无需重启即可重载热键 |
| 技术要点 | tauri-plugin-global-shortcut |

#### F4: 快速数字键粘贴

| 属性 | 内容 |
|------|------|
| 描述 | 使用 `Ctrl+Alt+数字键` 快速选择并粘贴历史记录 |
| 用户场景 | 用户按 `Ctrl+Alt+1` 到 `Ctrl+Alt+9`，对应记录立即粘贴到当前应用 |
| 验收标准 | 1. `Ctrl+Alt+1` 到 `Ctrl+Alt+9` 对应列表前 9 条记录<br>2. 粘贴后窗口自动隐藏 |
| 技术要点 | 监听键盘事件，调用系统剪贴板 API，模拟 Ctrl+V 粘贴 |

#### F5: 搜索功能

| 属性 | 内容 |
|------|------|
| 描述 | 按关键词搜索历史记录 |
| 用户场景 | 用户输入关键词，列表实时过滤匹配内容 |
| 验收标准 | 1. 搜索响应时间 < 50ms<br>2. 支持预览文本和非图片内容的包含匹配<br>3. 搜索框自动聚焦 |
| 技术要点 | SQLite LIKE 包含查询，前端防抖处理 |

#### F6: 删除历史记录

| 属性 | 内容 |
|------|------|
| 描述 | 删除单条或全部历史记录 |
| 用户场景 | 用户右键或点击删除按钮移除不需要的内容 |
| 验收标准 | 1. 支持删除单条记录<br>2. 支持清空全部记录<br>3. 删除操作有确认提示 |
| 技术要点 | 数据库 DELETE 操作 |

#### F7: 系统托盘常驻

| 属性 | 内容 |
|------|------|
| 描述 | 应用在系统托盘运行，不占用任务栏 |
| 用户场景 | 用户关闭窗口后，应用继续在托盘运行 |
| 验收标准 | 1. 托盘图标显示应用状态<br>2. 托盘菜单支持常用操作<br>3. 点击托盘图标显示窗口 |
| 技术要点 | Tauri TrayIcon API |

#### F8: 本地 SQLite 存储

| 属性 | 内容 |
|------|------|
| 描述 | 所有数据存储在本地 SQLite 数据库 |
| 用户场景 | 用户数据完全本地化，无需网络 |
| 验收标准 | 1. 数据库文件在用户目录<br>2. 当前版本完成基础本地存储能力<br>3. 当前版本提供 JSON/CSV 导入导出和数据库备份/恢复<br>4. 当前版本具备 schema 版本门禁、轻量迁移、损坏数据库保留与干净重建能力 |
| 技术要点 | rusqlite crate，数据目录管理 |

#### F9: 应用配置持久化

| 属性 | 内容 |
|------|------|
| 描述 | 用户设置自动保存和加载 |
| 用户场景 | 用户修改设置后，下次启动保持配置 |
| 验收标准 | 1. 配置存储在数据库<br>2. 提供默认配置<br>3. 当前后端运行时消费 `hotkey_toggle_window`、`hotkey_quick_paste_prefix`，并支持 `auto_start` 同步系统自启动状态 |
| 技术要点 | 配置表存储，JSON 序列化 |

#### F10: 开机自启动

| 属性 | 内容 |
|------|------|
| 描述 | 可选开机时自动启动应用，并将系统状态与数据库配置保持一致 |
| 用户场景 | 安装包阶段由用户显式启用后，每次开机自动运行 Klip |
| 验收标准 | 1. 用户可显式开启或关闭系统自启动<br>2. 应用启动时按 `auto_start` 配置同步系统状态<br>3. 以 Windows 为主验证，其他平台作为后续阶段补充验证 |
| 技术要点 | tauri-plugin-autostart 或平台 API |

## 3. 非功能需求

### 3.1 性能指标

| 指标 | 目标值 |
|------|--------|
| 冷启动时间 | < 1 秒 |
| 热启动时间 | < 200ms |
| 内存占用 (空闲) | < 50MB |
| 内存占用 (100条记录) | < 100MB |
| 剪贴板监听延迟 | < 100ms |
| 搜索响应时间 | < 50ms |
| 安装包大小 | < 10MB |

### 3.2 兼容性

| 平台 | 版本要求 |
|------|----------|
| Windows | Windows 10+（当前实现目标） |
| macOS | macOS 11+ (Big Sur)（后续阶段） |
| Linux | Ubuntu 20.04+, Fedora 35+（后续阶段） |

### 3.3 安全性

- 本地数据存储，不上传云端
- 可选敏感内容检测（密码、密钥等）
- 数据库文件权限控制

### 3.4 可维护性

- 模块化代码结构
- 单元测试覆盖率 >= 80%
- 完整的 API 文档

## 5. 验收标准

### 5.1 MVP 验收清单

- [ ] 应用正常安装和启动
- [ ] 剪贴板监听正常工作
- [ ] 文本、图片、文件正确识别
- [ ] 快捷键唤起窗口正常
- [ ] 数字键快速粘贴正常
- [ ] 搜索功能正常
- [ ] 删除功能正常
- [ ] 系统托盘正常显示
- [ ] 设置保存和加载正常
- [ ] 安装包阶段验证开机自启动
- [ ] 性能指标达标
- [ ] 无明显 Bug

### 5.2 测试场景

1. **基础流程**: 复制 → 显示在列表 → 点击粘贴
2. **搜索流程**: 打开窗口 → 输入关键词 → 过滤结果
3. **快捷键流程**: 按 Ctrl+Alt+K → 窗口显示 → 按 Ctrl+Alt+1 → 粘贴
4. **托盘流程**: 关闭窗口 → 托盘图标存在 → 点击显示窗口
